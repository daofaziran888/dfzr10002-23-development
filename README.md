# 数据分析工作台

面向企业数据分析师与数据产品经理的一站式数据分析工作台。提供指标口径管理、聚合查询、分析实验设计、数据服务发布与应用集成的完整链路。

这是一个前后端分离的管理平台：前端 React + Vite + TypeScript，后端 FastAPI（Python）。
两边各自独立启动，前端 dev server 已关掉自动打开页面，启动后按终端打印的地址手工打开。

## 目录结构

```text
.
├── frontend/                 React + Vite + TypeScript 前端
│   ├── src/views/            每个业务模块一个页面
│   ├── src/api/              统一请求封装
│   ├── src/stores/           会话与筛选状态
│   └── vite.config.ts        dev server 配置（open: false）
├── backend/                  FastAPI（Python） 后端
│   ├── app/routers/          每个业务模块一组接口
│   ├── app/services/         业务规则与状态流转
│   └── app/store.py          内存数据仓库与示例数据
├── .gitignore
└── docker-compose.yml
```

## 启动

### 后端

```bash
cd backend
python3 -m venv .venv && .venv/bin/pip install -r requirements.txt
./run.sh
```

健康检查：`curl http://127.0.0.1:8000/api/health`

### 前端

```bash
cd frontend
npm install
npm run dev
```

前端默认监听 `http://127.0.0.1:5173/`，dev server 不会自动打开浏览器，
需要自己访问。`/api` 由 vite 代理到后端 `http://127.0.0.1:8000`。

## 定时调度窗口预演

定时分析任务在启用前必须先做「窗口冲突预演」，预演结果确认后才允许进入调度队列。
调度口径集中在 `backend/app/services/scheduling.py`：

| 口径 | 规则 |
| --- | --- |
| 时区 | 每条任务自带 IANA 时区（默认 `Asia/Shanghai`）；窗口先换算成 UTC 绝对时间再比较 |
| 优先级 | `P1 > P2 > P3`，由业务登记时指定；同级按任务编号升序，结果可复现 |
| 执行窗口 | 5–240 分钟，任务从开始时刻起独占该时长 |
| 冲突阈值 | 0–120 分钟且必须小于执行窗口；重叠分钟数超过双方更严格的阈值才算冲突 |
| 顺延 | 高优先级任务保持原定时间，低优先级任务顺延到冲突窗口结束；跨午夜按本地日历自然顺延 |
| 允许提交 | 必填字段齐全、cron 五段合法、时区可识别、输出目标非空；启用前还需「预演已确认」 |

流程：

1. `POST /api/schedule/preview`：表单未保存时用分析类型、输出目标、通知渠道等参数做试算。
2. `POST /api/schedule/{id}/preview`：对已保存配置生成正式预演（未来 5 次运行、冲突任务、顺延原因、受影响报告）。
3. `POST /api/schedule/{id}/preview/confirm`：确认顺延方案。配置在预演后变更会使预演失效，需重新预演。
4. `POST /api/schedule/{id}/actions`（`启用配置`）：通过规则与确认检查后进入调度队列。
5. 预演结果同步到分析报告清单：`计划生成时间`、`顺延分钟`、`冲突任务`、`顺延原因` 与 `预演指纹` 一致。
6. 运行按 `数据准备 → 生成报告 → 分发通知` 推进；`POST /api/schedule/{id}/runs` 可复现失败，
   再次调用即从失败阶段续跑；实际开始晚于计划时，后续运行与报告队列同步顺延。

示例：每天 23:50 的日报任务与 23:20–00:20 的销售日报窗口重叠 30 分钟，预演结果为
次日 **00:20** 开始、00:50 结束，并列出冲突任务 `SCHE-0001` 与受影响报告；确认启用后才入队。

## 约定

- 每个模块的前端页面在 `frontend/src/views/<模块>/index.vue`，后端接口在
  `backend/app/routers/<模块>.py`，业务规则在 `backend/app/services/<模块>.py`。
- 列表接口统一返回 `{ items, total, page, size }`，动作接口统一返回 `{ ok, message }`。
- 状态流转只允许在 `app/services` 里改，路由层不做业务判断。
